# Design Patterns Justification (C8)

Every design pattern in FlagShip solves a concrete architectural requirement from CSE 444. No pattern was introduced speculatively.

| Pattern | Requirement Supported | Problem Solved | Participating Classes / Modules | Why Selected | Alternative Rejected |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Strategy** | FR2 (Targeting Operators), FR3 (Rollout Bucketing) | Supporting 8 heterogeneous comparison operators (`EQUALS`, `SEMVER_GREATER_THAN`, `REGEX`, dates) and swappable hashing algorithms without giant `if/else` chains. | `OperatorStrategy`, `OperatorRegistry` (`src/engine/targeting.ts`); `BucketingStrategy`, `Murmur3BucketingStrategy` (`src/engine/hashing.ts`, `MurmurHash3.java`). | Open/Closed extensibility: new operators register cleanly in O(1) lookup with unit-testable isolation. | Monolithic `switch` statements inside the evaluator (harder to extend and test independently). |
| **Composite** | FR2 (Nested AND/OR Rule Groups) | Evaluating arbitrarily nested boolean logic trees (e.g., `(plan == enterprise AND version > 2.0) OR country IN [US, CA]`). | `RuleNode`, `ConditionLeaf`, `RuleGroup` (`src/types/flagship.ts`, `EvaluationEngine.RuleGroup`). | Uniform recursive representation of leaf conditions and compound groups. | Flat list of AND-only rules (fails nested AND/OR course requirement). |
| **Visitor** | FR2 (Rule Evaluation & Validation) | Performing multiple distinct tree operations (runtime evaluation vs. save-time regex/date validation) without polluting rule data structures. | `RuleNodeVisitor<T>`, `RuleEvaluationVisitor`, `RuleValidationVisitor`, `acceptRuleNode` (`src/engine/targeting.ts`). | Separates AST/JSON data records from operations so serialization remains pure JSON. | Embedding `evaluate()` and `validate()` methods directly on DTOs (couples persistence models to runtime services). |
| **Chain of Responsibility** | FR2 (Strict 5-Stage Evaluation Order) | Guaranteeing strict deterministic precedence: `Kill Switch -> Individual Target -> Segment/Rules -> Rollout -> Default`. | `EvaluationHandler`, `KillSwitchHandler`, `IndividualTargetHandler`, `SegmentAndRuleHandler`, `PercentageRolloutHandler`, `DefaultVariationHandler` (`src/engine/evaluation.ts`). | Each precedence tier is self-contained, short-circuits immediately on match, and is trivial to inspect or reorder. | Deeply nested `if/return` pyramid in one 200-line method. |
| **Observer** | FR5 (Live SSE Updates), QA3 (<5s Propagation) | Decoupling configuration mutations from real-time fan-out to connected SDK SSE streams and dashboard clients. | `FlagShipEventBus`, `SseSubscriber`, `FlagShipDomainEvent` (`server/eventBus.ts`). | Multiple independent listeners (SSE streams, dashboard refresh, telemetry) react without coupling publishers to transport details. | Synchronous polling from SDK every second (wastes CPU/network and increases propagation tail latency). |
| **Proxy / Decorator** | FR4 (Spring Boot Starter), FR6 (Offline Resilience), QA1 (<50µs) | Wrapping raw evaluation with local in-memory caching, disk snapshot persistence, <=2s startup timeout, exception shielding, and Micrometer metrics. | `FlagShipClient`, `SnapshotStorage`, `FlagShipAutoConfiguration.FeatureFlagAspect` (`src/engine/sdkClient.ts`, `FlagShipClient.java`). | Application code sees a clean typed API (`isEnabled`, `getString`) while caching, resilience, and metrics remain transparent. | Direct REST HTTP call per flag evaluation (violates QA1 50µs latency and QA2 offline resilience). |
| **Command** | FR7 (Versioning, Audit, Rollback, Approvals) | Executing flag mutations and rollbacks as atomic, auditable, reversible units capturing before/after snapshots. | `FlagCommand`, `ApplyFlagConfigCommand`, `RollbackFlagConfigCommand` (`server/commands.ts`). | Centralizes version increments, hygiene timestamps, audit logging, and SSE publishing across direct edits, approvals, schedules, and rollbacks. | Duplicating mutation/versioning/SSE logic across 5 separate REST controller endpoints. |
| **Builder** | FR2/FR4 (Evaluation Context Construction) | Ergonomically constructing immutable `EvaluationContext` objects with mandatory `userKey` and optional typed attributes. | `EvaluationContextBuilder` (`src/engine/evaluation.ts`, `EvaluationEngine.EvaluationContext.Builder`). | Prevents invalid empty `userKey` states and improves SDK readability for Java/TS consumers (QA5). | Telescoping constructors or mutable raw `Map<String, Object>` arguments. |
